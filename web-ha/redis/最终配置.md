# Redis 高可用 — 最终配置（两机方案）

## 架构

```
192.168.131.10 (app10)                    192.168.131.11 (app11)
┌─────────────────┐                 ┌─────────────────┐
│ Redis Master    │                 │ Redis Slave     │
│                 │─── 数据同步 ───►│                 │
│ replica-priority│                 │ replica-priority│
│      = 100      │                 │      = 50       │
│                 │                 │                 │
│ Sentinel :26379 │◄── 互相监控 ──►│ Sentinel :26379 │
└─────────────────┘                 └─────────────────┘

SpringBoot → Sentinel(192.168.131.10:26379, 192.168.131.11:26379) → 自动获取 Master 地址
```

## 清理

```bash
# 两台都执行
cd /opt/redis-ha
docker compose down
rm -f sentinel.conf sentinel.conf.* docker-compose.yml
docker ps -a | grep redis && docker rm -f $(docker ps -aq --filter name=redis) 2>/dev/null
docker ps -a | grep sentinel && docker rm -f $(docker ps -aq --filter name=sentinel) 2>/dev/null
```

## app10 配置（192.168.131.10 — Redis Master + Sentinel）

### 1. sentinel.conf（和 app11 完全一样）

```bash
mkdir -p /opt/redis-ha/redis-data

cat > /opt/redis-ha/sentinel.conf << 'SENTINEL'
sentinel monitor redis-ha 192.168.131.10 6379 1
sentinel auth-pass redis-ha cns@2035
sentinel down-after-milliseconds redis-ha 5000
sentinel failover-timeout redis-ha 60000
sentinel parallel-syncs redis-ha 1
sentinel known-replica redis-ha 192.168.131.11 6379
SENTINEL
```

### 2. docker-compose.yml

```bash
cat > /opt/redis-ha/docker-compose.yml << 'COMPOSE'
services:

  redis:
    image: redis:7-alpine
    container_name: redis-ha
    network_mode: host
    restart: always
    command: >
      redis-server
      --port 6379
      --requirepass cns@2035
      --masterauth cns@2035
      --maxmemory 512mb
      --maxmemory-policy allkeys-lru
      --save ""
      --appendonly no
      --loglevel notice
      --replica-priority 100
    volumes:
      - /opt/redis-ha/redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "cns@2035", "--no-auth-warning", "PING"]
      interval: 10s
      timeout: 3s
      retries: 3

  sentinel:
    image: redis:7-alpine
    container_name: sentinel-ha
    network_mode: host
    restart: always
    command: redis-sentinel /etc/redis/sentinel.conf --port 26379
    volumes:
      - /opt/redis-ha/:/etc/redis/
    depends_on:
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "redis-cli", "-p", "26379", "PING"]
      interval: 10s
      timeout: 3s
      retries: 3
COMPOSE

docker compose up -d
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning PING
# PONG
docker exec sentinel-ha redis-cli -p 26379 PING
# PONG
```

## 验证（等 app11 启动 15 秒后执行）

```bash
# 1. 主从状态
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE
# app10 → master
# app11 → slave, connected

# 2. Sentinel 识别的拓扑
docker exec sentinel-ha redis-cli -p 26379 SENTINEL MASTER redis-ha | grep -E "ip|port|num-slaves"
# ip: 192.168.131.10  port: 6379  num-slaves: 1

docker exec sentinel-ha redis-cli -p 26379 SENTINEL SLAVES redis-ha
# 必须非空

# 3. Sentinel 已自动写入 known-replica
grep "known" /opt/redis-ha/sentinel.conf
# sentinel known-replica redis-ha 192.168.131.11 6379  ← Sentinel 自动写入

# 4. 数据同步测试
ssh app10 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning SET test:sync ok"
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning GET test:sync
# "ok"
```

## 故障切换测试

```bash
# 1. 停 app10 Redis
ssh app10 "cd /opt/redis-ha && docker compose stop redis"

# 2. 等 10 秒看 app11 日志
docker compose logs sentinel | grep -E "sdown|odown|switch-master" | tail -5
# +switch-master redis-ha 192.168.131.10 6379 192.168.131.11 6379

# 3. app11 角色
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE
# master ← 已自动提升

# 4. 恢复 app10
ssh app10 "cd /opt/redis-ha && docker compose start redis"
# app10 自动以 Slave 加入

# 5. 人工切回 app10 为 Master（业务低峰期）
docker exec sentinel-ha redis-cli -p 26379 SENTINEL FAILOVER redis-ha
```

## 配置参数说明

| 参数 | app10 | app11 | 作用 |
|------|-------|-------|------|
| `--replica-priority` | 100 | 50 | Sentinel 优先选高分节点为 Master；满足"始终优先用 app10" |
| `--replicaof` | 无 | `192.168.131.10 6379` | app11 启动即连 app10 做 Slave |
| `--replica-read-only no` | — | yes | 被提升后可接受写入 |
| `--replica-serve-stale-data yes` | — | yes | Master 不在线时仍可响应读请求 |
| `quorum=1` | — | — | 双机环境，1 票即可触发切换 |

## 覆盖场景

| 场景 | 行为 |
|------|------|
| 正常运行 | app10=Master, app11=Slave, 数据实时同步 |
| app10 宕机 | Sentinel 5s 检测, 自动提升 app11 为 Master |
| app10 恢复 | 以 Slave 加入, 数据从 app11 同步回来 |
| app11 宕机 | app10 正常运行, 暂时失去高可用 |
| app11 恢复 | 自动 Slave 加入, 恢复高可用 |
| 双机重启 | Sentinel 从配置文件读取拓扑, 恢复主从 |
| 人工切回 | 低峰期执行 SENTINEL FAILOVER, app10 恢复 Master |
