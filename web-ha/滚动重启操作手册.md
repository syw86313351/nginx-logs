# 滚动重启 / 滚动升级操作手册

## 核心原则

**先备后主，逐台验证。** 始终保证至少一台机器在对外服务。

---

## 操作流程总览

```
升级 app11（备机）              升级 app10（主机）
───────────────                ───────────────
1. 确认当前状态                5. 确认 VIP 在 app11
2. 停 app11 服务               6. 停 app10 服务
3. 升级/重启 app11             7. 升级/重启 app10
4. 验证 app11 恢复             8. 验证 app10 恢复
                               VIP 自动漂回 app10
```

---

## 第 1 步：操作前确认状态

```bash
# ── 确认当前谁是 MASTER ──
# 正常情况下 VIP 在 app10 上
ssh app10 "ip addr show enp125s0f0-br0 | grep 192.168.131.100"
# 有输出 → VIP 在 app10 ✓

ssh app11 "ip addr show enp125s0f0-br0 | grep 192.168.131.100"
# 无输出 → VIP 不在 app11 ✓

# ── 确认 Redis 主从正常 ──
ssh app10 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE"
# → master ✓

ssh app11 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE"
# → slave ✓
ssh app11 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning INFO replication | grep master_link_status"
# → master_link_status:up ✓

# ── 确认服务可访问 ──
curl http://192.168.131.100/health
# → OK ✓
```

---

## 第 2 步：重启 app11（备机，不影响线上）

app11 是 BACKUP，上面没有 VIP，停了不影响用户。

### 2.1 停 app11 上的所有服务

```bash
ssh app11

# 停 Keepalived（先停，避免它乱抢 VIP）
systemctl stop keepalived

# 停 Nginx 和 Redis/Sentinel
systemctl stop nginx
cd /opt/redis-ha && docker compose stop
```

### 2.2 执行升级 / 重启

```bash
# ── 系统更新（如果需要）──
dnf update -y

# ── 直接重启整机（最彻底）──
reboot
```

### 2.3 app11 启动后验证

```bash
# 等机器起来后 SSH 过去
ssh app11

# ── 确认 Docker 启动了 ──
docker ps
# → redis-ha Up, sentinel-ha Up

# ── 启动 Nginx ──
systemctl start nginx
curl http://127.0.0.1/health
# → OK

# ── 启动 Keepalived ──
systemctl start keepalived

# ── 确认 Redis 主从恢复 ──
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE
# → slave ✓
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning INFO replication | grep master_link_status
# → master_link_status:up ✓     ← ★ 必须确认

# ── 确认 VIP 没被抢走 ──
ip addr show enp125s0f0-br0 | grep 192.168.131.100
# 应无输出 ← app11 是 BACKUP，不应持有 VIP
```

---

## 第 3 步：手动切换 VIP 到 app11

在重启 app10 之前，先把 VIP 切到 app11，避免断流。

```bash
# 方式一: 在 app10 上主动停 Keepalived（最快）
ssh app10 "systemctl stop keepalived"

# 等待 3 秒

# 验证 VIP 已漂移到 app11
ssh app11 "ip addr show enp125s0f0-br0 | grep 192.168.131.100"
# 应有输出 → VIP 已到 app11 ✓

# 验证服务正常
curl http://192.168.131.100/health
# → OK ✓
```

---

## 第 4 步：重启 app10（主机）

### 4.1 停 app10 服务

```bash
ssh app10

# Keepalived 已经在上一步停了
systemctl stop nginx
cd /opt/redis-ha && docker compose stop
```

### 4.2 执行升级 / 重启

```bash
dnf update -y   # 如果需要
reboot          # 重启
```

### 4.3 app10 启动后恢复服务

```bash
ssh app10

# ── 启动 Nginx ──
systemctl start nginx
curl http://127.0.0.1/health

# ── 启动 Docker Compose（Redis + Sentinel）──
cd /opt/redis-ha && docker compose up -d

# ── 确认 Redis 角色 ──
docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE
# → slave（app10 恢复后自动以 Slave 加入，因为 Sentinel 已把 app11 提升为 Master）

# ── 启动 Keepalived ──
systemctl start keepalived
# 因为 app10 priority=100 > app11 priority=90
# VIP 会自动从 app11 漂回 app10
```

---

## 第 5 步：最终验证

```bash
# ── VIP 回到 app10 ──
ssh app10 "ip addr show enp125s0f0-br0 | grep 192.168.131.100"
# 应有输出 ✓

ssh app11 "ip addr show enp125s0f0-br0 | grep 192.168.131.100"
# 应无输出 ✓

# ── Redis 主从 ──
# 此时谁是 Master 取决于 Sentinel 选举，不一定是 app10
# 这不影响服务，Sentinel 会自动管理
ssh app10 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE"
ssh app11 "docker exec redis-ha redis-cli -a cns@2035 --no-auth-warning ROLE"
# 一个 master，一个 slave 即可 ✓

# ── 服务可访问 ──
curl http://192.168.131.100/health
# → OK ✓
```

## 附：一键滚动重启脚本

如果你需要自动化，把这个脚本放到任意一台能 SSH 到 app10/app11 的机器上：

```bash
#!/bin/bash
# 滚动重启脚本 — 先 app11(备机) 后 app10(主机)
# 确保始终有一台机器在对外服务

set -e

APP10="192.168.131.10"
APP11="192.168.131.11"
VIP="192.168.131.100"
PASS="cns@2035"

echo "=== 1/5 确认初始状态 ==="
ssh root@$APP10 "ip addr show enp125s0f0-br0 | grep $VIP" && echo "VIP 在 app10 ✓" || echo "⚠ VIP 不在 app10"

echo ""
echo "=== 2/5 重启 app11（备机）==="
ssh root@$APP11 "systemctl stop keepalived nginx; cd /opt/redis-ha && docker compose stop"
ssh root@$APP11 "reboot" || true
echo "等待 app11 重启..."
sleep 120  # 等 2 分钟机器起来

echo "app11 启动后恢复服务..."
ssh root@$APP11 "docker compose -f /opt/redis-ha/docker-compose.yml up -d; systemctl start nginx keepalived"
ssh root@$APP11 "docker exec redis-ha redis-cli -a $PASS --no-auth-warning INFO replication | grep master_link_status | grep -q up" \
    && echo "app11 Redis 同步正常 ✓" || echo "⚠ 请手动检查 app11"

echo ""
echo "=== 3/5 切换 VIP 到 app11 ==="
ssh root@$APP10 "systemctl stop keepalived"
sleep 5
ssh root@$APP11 "ip addr show enp125s0f0-br0 | grep $VIP" && echo "VIP 已到 app11 ✓" || echo "⚠ 手动检查"

echo ""
echo "=== 4/5 重启 app10（主机）==="
ssh root@$APP10 "systemctl stop nginx; cd /opt/redis-ha && docker compose stop"
ssh root@$APP10 "reboot" || true
echo "等待 app10 重启..."
sleep 120

echo "app10 启动后恢复服务..."
ssh root@$APP10 "docker compose -f /opt/redis-ha/docker-compose.yml up -d; systemctl start nginx keepalived"

echo ""
echo "=== 5/5 最终验证 ==="
sleep 10
ssh root@$APP10 "ip addr show enp125s0f0-br0 | grep $VIP" && echo "VIP 回到 app10 ✓"
curl -sf --connect-timeout 3 http://$VIP/health && echo "服务正常 ✓" || echo "⚠ 请手动检查"
echo "完成！"
```

## 关键点总结

| 要点 | 说明 |
|------|------|
| 顺序 | 永远先重启 BACKUP(app11)，再重启 MASTER(app10) |
| 切换 VIP | 重启 MASTER 前，先 `systemctl stop keepalived` 让 VIP 漂到备机 |
| Redis 角色 | 重启后不一定是 app10 当 Master，这不影响服务，Sentinel 自动管理 |
| 验证 | 每次重启后必须确认 `master_link_status:up` 和 `curl VIP/health` |
| systemd enable | 所有服务都已 `systemctl enable`，重启后会自动拉起 |
