西信机房网络改造

项目范围华为 USG6305E 防火墙 · 千兆交换机（C06 / D03 / D04）· 万兆交换机 · 服务器群
目标防火墙承接 B 组网关 / NAT · 西信电信新线路 XGE0/0/0 · 阿里云 Nginx 高可用代理
文档版本 3.0 2026-05-29 作者：shu_yw

汇报结论

核心改造

防火墙承接 B 组出网（GE0/0/7 接 10.0.0.0/24）；GE0/0/0 极云入网不动，XGE0/0/0 西信电信 WAN（182.140.240.121）。网关二选一：10.0.0.11 或 10.0.0.254。详见 网关方案。

不改什么

A 组公网（ws1/2/3/5/6/7、dev、dev-2）出网路径不变；ws1 业务网卡（Gb2）无需停用，两种方案均保持网卡在线。

预期收益

去除 ws1 NAT 单点，B 组经防火墙统一策略出网；方案甲割接最快（零改主机网关），方案乙网关地址独立便于长期规划。

风险与控制

主要风险是现场参数不一致（公网 IP、VLAN ID、端口号）。控制策略：先灰度 1~2 台验证，再分批迁移；若异常，单台改回旧网关即可恢复。

备节点 · 回源 IP

回源 IP：182.140.146.150（不依赖西信新线，独立出网路径）
ws6（182.140.240.121）全部不可用时，Nginx 自动切换至此回源地址。
与主节点物理路径隔离，避免单点故障影响业务。
三地阿里云 ECS 统一 Nginx upstream 配置
以下配置部署在广州、上海、北京每台阿里云 ECS 的 Nginx 中。阿里云通过公网 IP 直连机房节点，主备 同在一个 upstream 块，任一云端节点独立工作即可对外服务。
upstream backend_150 {
    server 182.140.240.121 max_fails=3 fail_timeout=60s;  # 主节点（西信骨干）
    server 182.140.146.150 backup;                         # 备节点（回源IP）
    keepalive 128;
    keepalive_requests 10000;
    keepalive_timeout 60s;
}

server {
    listen 80;
    listen 443 ssl;
    server_name *.150-domain.com;

    location / {
        proxy_pass http://backend_150;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_next_upstream error timeout http_502 http_503 http_504;
        proxy_next_upstream_tries 2;
        proxy_connect_timeout 3s;
    }
}
故障自动切换：三地 Nginx 通过 proxy_next_upstream + backup 参数实现
主节点 182.140.240.121 健康检查失败（超时 / HTTP 5xx）→ 自动转发到回源 IP 182.140.146.150 → 用户无感知
关键结论：ws6 网络不在线不影响 150 网段业务正常使用
  • 三地阿里云 Nginx 通过公网 IP 分别连接主节点和回源 IP，物理路径隔离，任一链路中断均可自动切换。
  • Nginx 健康检查持续探测主节点 182.140.240.121，一旦不可达，自动将流量切到回源 IP 182.140.146.150。
  • 回源 IP 不依赖西信新线路 XGE0/0/0——即使西信线路中断 + ws6 同时宕机，150 网段业务仍可正常对外服务。
  • 因此：在配置 ws6 网络（西信新线 + 防火墙）的整个过程中，理论上 150 网段业务不受任何影响，运维人员可放心操作，无需担心业务中断。
运维提示：割接前确认三地 Nginx 的 upstream 配置中 backup 参数及 keepalive 长连接已生效，并在割接窗口前手动执行一次健康检查验证。

0.1 防火墙业务网关方案（二选一）

迁移目标：由 华为 USG6305E 承接原 ws1（10.0.0.11）上的 B 组 NAT/网关职能；西信电信新线路经 XGE0/0/0 直连骨干，业务网经 GE0/0/7 接入 10.0.0.0/24（见 0.2.3、0.2.4）。以下两种方案择一实施；无论选哪种，ws1 的 Gb2 业务网卡均无需停机或拔线。

方案乙 · 推荐

防火墙网关 = 10.0.0.254

10.0.0.254 / 24（独立新网关地址 · 与 .11 解耦）

出口 IP 统一不变 保留 ws1 DNAT 热备 灰度可控·可随时退回
  • 在防火墙 GE0/0/7（路由模式）配置 LAN 地址 10.0.0.254/24，作为 B 组全新业务网关。✓ 与 ws1 Gb2（.11）IP 不冲突，防火墙和 ws1 可以长期共存。
  • 核心优势① 出口 IP 不变化：B 组主机经防火墙 XGE0/0/0（182.140.240.121） 统一 SNAT 出网后，所有 B 组主机的公网出口 IP 全部统一为 182.140.240.121，不再经过 ws1 的 NAT IP，出口地址完全独立可控。
  • 核心优势② 保留 ws1 DNAT 网络：ws1 上的 DNAT/端口映射规则可完整保留不动，作为热备回退通道。万一防火墙出问题，B 组主机随时可单台改回网关 .11，立即恢复走 ws1 旧路，无需动防火墙任何配置。
  • 核心优势③ 灰度迁移零风险：ws4、ws8、ws11~ws19 共 11 台主机，逐台改网关为 .254 → 逐台验证 → 通过后再下一台。任何一台不通，单台改回 .11 即可恢复，不影响其他已切换主机。
方案甲 · 备选

防火墙网关 = 10.0.0.11

10.0.0.11 / 24（直接抢占 ws1 网关地址）

IP 冲突风险 无法热备共存 需同步插线
  • 在防火墙 GE0/0/7 配置 10.0.0.11/24，直接接管 ws1 网关地址。✗ 与 ws1 Gb2 的 .11 IP 冲突，两者不能同时在线。
  • ws4、ws8、ws11~ws19 默认网关保持 10.0.0.11 不变，服务器侧零改动。但这意味着必须确保 ws1 Gb2 先断开（或 ws1 整机关机），防火墙 GE0/0/7 再插线启用 .11，存在操作时序窗口，切换期间服务中断。
  • 限制①：ws1 DNAT 网络必须被完全替换。一旦防火墙接管 .11，ws1 的所有 NAT 规则必须全部迁移到防火墙后才能工作，期间任何遗漏的 DNAT 端口都会中断。
  • 限制②：回滚需要关闭 GE0/0/7 → 重新启用 ws1 Gb2 和 NAT，操作步骤多、窗口长，不如方案乙单台改网关快。
  • 适用：仅当必须在单次割接窗口内完成全部切换、且接受 ws1 完全下线的场景。
对比项方案甲 · 10.0.0.11方案乙 · 10.0.0.254
防火墙配置（GE0/0/7）10.0.0.11/24（承接现网网关地址）10.0.0.254/24（新地址）
ws4 / ws8 / ws11~ws19 默认网关不改（仍为 10.0.0.11）分步改为 10.0.0.254
ws1 Gb2 网卡两种方案均保持在线，不强制停用
ws1 NAT 服务防火墙就绪后择机停用 ws1 NAT同左；主机改 .254 后再停 ws1 NAT
割接复杂度低（服务器侧零网关变更）中（需分批改 11 台网关：ws4/ws8 + ws11~19）
回滚防火墙切回或恢复 ws1 NAT单台改回网关 10.0.0.11

割接实施详细步骤（方案乙 · 推荐 vs 方案甲 · 备选 对照）

以下 7 步覆盖换线 → 配置 → 策略 → 转发 → 主机 → 验证 → 访问测试全流程。方案乙（推荐）为新网关 .254 模式，方案甲（备选）为抢占 ws1 .11 模式。

方案乙 · 10.0.0.254（推荐） 新网关独立地址 · ws1 DNAT 热备保留 · 可灰度平滑迁移

📍 第一步：物理接线（割接前完成）

  • ① 西信光纤 → 防火墙 XGE0/0/0（万兆光口），核对光模块类型（单模/多模），运营商标签「西信电信 182.140.240.121/25」
  • ② 千兆网线 → 防火墙 GE0/0/7，另一端接至三柜千兆交换机 VLAN30 业务网 Access 口（Eth1/0/x，现场确认口编号后记录）
  • ③ 核对链路：XGE0/0/0 指示灯亮（光口 LINK/ACT）· GE0/0/7 指示灯亮（电口 LINK/ACT）

📍 第二步：防火墙接口配置

  • ① Web 登录：浏览器访问 https://192.168.10.210:8443（MEth0/0/0 带外管理口，确保终端在 192.168.10.x 网段）
  • ② 备份配置：系统 → 配置文件管理 → 导出当前配置（display current-configuration），割接前必须完成
  • ③ 配置 XGE0/0/0：网络 → 接口 → XGE0/0/0 → 路由模式 → 安全域 untrust → IP 182.140.240.121/25 → 启用
  • ④ 配置 GE0/0/7：网络 → 接口 → GE0/0/7 → 路由模式 → 安全域 trust → IP 10.0.0.11/24 → 启用
  • ⑤ 添加静态路由：到 10.0.0.0/24 的直连路由（自动生成），默认路由指向 182.140.240.1（仅 XGE0/0/0 侧）

📍 第三步：防火墙安全策略

  • ① 安全域检查：untrust（XGE0/0/0 + GE0/0/0）↔ trust（GE0/0/7 + GE0/0/1/2/3）
  • ② 策略规则：允许 trust → untrust（内网出公网）；允许 untrust → trust（按需 DNAT 白名单）
  • ③ ws6 专用策略：源 10.0.0.16/32 出接口限定 XGE0/0/0（策略路由），禁止 ws6 从极云 GE0/0/0 出网
  • ④ 策略路由：网络 → 策略路由 → 新建 → 匹配源 10.0.0.16 → 强制下一跳出接口 XGE0/0/0

📍 第四步：NAT 转发配置（.254 独立地址 · 无 IP 冲突 · 可提前预配）

  • ① SNAT（B 组出网）：策略 → NAT → 源 NAT → 源 trust → 目标 untrust → 源地址 10.0.0.0/24（B 组主机）→ 转换方式 出接口地址（XGE0/0/0: 182.140.240.121）
  • ② 迁移 ws1 DNAT 规则：在 ws1 上导出全部 NAT 规则清单 → 逐条录入防火墙（DNAT/端口映射/源地址转换），逐条核对端口号与内网 IP 对应关系
  • ③ ws6 端口映射：策略 → NAT → 目标 NAT → 公网 182.140.240.121:端口 → 映射到 10.0.0.16:端口（按实际业务端口配置）
  • ④ 优势：GE0/0/7 使用 10.0.0.254（独立地址），与 ws1 Gb2 (10.0.0.11) 不冲突——防火墙和 ws1 可同时在线共存，NAT 规则可提前预配验证，无需掐秒插拔网线

📍 第五步：ws6 服务器 + B 组主机侧配置（方案乙关键：逐台灰度改网关）

  • ① 停用 Gb1 公网 IP：在网络适配器中禁用或删除 Gb1 上的公网 IP 配置（182.140.240.121 将仅存在于防火墙）
  • ② 确认 Gb2 配置：IP 10.0.0.16 / 掩码 255.255.255.0 / 默认网关改为 10.0.0.254 / DNS 61.139.2.69
  • ③ 刷新路由：route print -4 确认默认路由指向 10.0.0.254，无残留旧网关
  • ④ ws4/ws8 Gb1：默认网关从 10.0.0.11 改为 10.0.0.254（C06 柜内两台，先改）
  • ⑤ ws11~ws19 Gb1：分批逐台改网关为 10.0.0.254（ws11→ws12→...→ws19，每台改完 ping 通后再下一台）
  • ⑥ 改网关方法：Windows → 网络适配器 → IPv4 属性 → 默认网关改为 .254；Linux → 修改 /etc/sysconfig/network-scripts/ifcfg-ethX 或 netplan 中的 gateway
  • ⑦ ws1 Gb2：保持 10.0.0.11 不变（防火墙 .254 与 ws1 .11 互不冲突，ws1 DNAT 作为热备保留）

📍 第六步：网络连通性验证

  • ① 防火墙侧：ping 182.140.240.1（运营商网关）→ ping 223.5.5.5（公网 DNS）→ 确认出网
  • ② B 组主机：ping 10.0.0.254（防火墙 GE0/0/7）→ 确认局域网通
  • ③ ws6 外网：从 ws6 ping 223.5.5.5 → 确认经 XGE0/0/0 出网（tracert 检查路径不走极云线）
  • ④ ws4/ws8/ws11~ws19：已改网关为 10.0.0.254，逐台 ping 通外网确认正常

📍 第七步：业务系统访问测试（逐台灰度）

  • ① HTTP/HTTPS：从外网（手机 4G/5G）访问各 B 组服务的公网域名或 IP+端口，确认可正常响应
  • ② ws6 业务：通过 DNAT 映射的端口从公网访问 ws6 各服务，验证端口转发正确
  • ③ 逐台灰度：先验证 ws6 → 再 ws4/ws8 → 再 ws11~ws19，每台验证通过后再下一台

1.2 第一步：XGE0/0/0（西信电信 WAN · 路由口）

西信机房来的光纤/网线接在万兆口 XGE0/0/0，作为独立 WAN，承载公网 182.140.240.121/25。

  1. 接线：西信电信机房线路接入防火墙 XGE0/0/0（万兆光口 #0）。
  2. 切换三层：接口 XGE0/0/0 → 路由模式（撤销交换/Access，CLI：undo portswitch）。
  3. 安全域：划入 untrust（或与现网其它 WAN 一致的外网区域）。
  4. IPv4 地址：
    • IP 地址：182.140.240.121
    • 子网掩码：255.255.255.128（即 /25）
    • 广播地址：182.140.240.127（/25 网段主机位全 1，供核对）
  5. 运营商网关：下一跳 / 默认路由指向 182.140.240.1（仅防火墙 WAN 侧使用，不要下发给内网服务器）。
  6. DNS（防火墙 或 转发用）：61.139.2.69（与 ws6 现网一致，可按运营商补充备用 DNS）。
  7. 启用接口：链路 Up 后，在防火墙上执行 ping 182.140.240.1，再 ping 外网地址（如 223.5.5.5）确认出网。

interface XGigabitEthernet0/0/0
 undo portswitch
 description XiXin-Telecom-WAN
 ip address 182.140.240.121 255.255.255.128
# 方式 A：接口上指定网关（视版本支持）
# gateway 182.140.240.1
# 方式 B：静态默认路由（仅走西信线时）
 ip route-static 0.0.0.0 0.0.0.0 182.140.240.1 preference 60

Web 操作（XGE0/0/0）：网络 → 接口 → 选中 XGE0/0/0 → 编辑 → 工作模式选路由（或取消交换/Access）→ 安全区域 untrust → IPv4：182.140.240.121 / 掩码 255.255.255.128 → 在「路由/网关」或「静态路由」中设下一跳 182.140.240.1 → 启用接口 → 保存并 ping 网关。

1.3 第二步：GE0/0/7（业务网 10.0.0.0/24 · 路由口）

GE0/0/7 用千兆电口直连 10.0.0.0/24 业务网（经三柜千兆交换机 VLAN30），作为 ws6、ws11~ws19 及 B 组 NAT 的内网网关所在物理口（不再单独使用 Vlanif 逻辑口，除非现场 Trunk 方案要求）。

  1. 接线：GE0/0/7 网线接至三柜千兆交换机的 VLAN30 业务网（与 ws4/ws6/ws8/ws11~19 所在广播域互通）。三柜千兆经 Eth1/0/48 柜间 Trunk（末口）；USG 经 GE0/0/2、GE0/0/3 等其它 GE 口，业务流量经交换汇聚到本口。
  2. 切换三层：接口 GE0/0/7 → 路由模式（undo portswitch）。
  3. 安全域：划入 trust（内网业务区）。
  4. IPv4 地址（二选一，与 0.1 节 方案一致）：
    • 方案甲：10.0.0.11/24（掩码 255.255.255.0）— B 组主机默认网关可不改
    • 方案乙：10.0.0.254/24 — B 组分步改默认网关
  5. 勿与 WAN 混淆：本口不要配置 182.140.240.x；运营商网关 182.140.240.1 仅出现在 XGE0/0/0。
  6. 启用接口：从任一台业务机（如 ws6 10.0.0.16）ping 网关 10.0.0.11 或 10.0.0.254，确认通。
  7. 可选：在防火墙上配置到 10.0.0.0/24 的直连路由或接口路由，确保三柜 VLAN30 网段均经 GE0/0/7 可达（若仅单线接入交换，通常学习/静态指向交换即可）。

 ip address 10.0.0.11 255.255.255.0   # 方案乙改为 10.0.0.254
# 本口为内网网关，不设 182.140.240.1

三、ws6 公网映射（无私网 IP → 防火墙 DNAT/SNAT）

改造前：ws6 的 Gb1 可能直连或持有公网配置。改造后：公网只存在于防火墙 WAN；ws6 仅 10.0.0.16。

3.1 源 NAT（SNAT）— ws6 访问互联网

  1. 打开 策略 → NAT策略 → 源NAT（或等价菜单）。
  2. 新建规则：源区域 trust → 目的区域 untrust（或 XGE0/0/0 所在区域）。
  3. 源地址：10.0.0.16/32（可填主机对象「ws6」）。
  4. 出接口：XGE0/0/0。
  5. 地址转换：转换为 出接口 IP 或 指定 IP 182.140.240.121。
  6. 放行安全策略：trust → untrust，源 10.0.0.16，允许所需服务（至少允许 DNS、HTTP/HTTPS 等按业务）。
  7. 在 ws6 上测试：ping 182.140.240.1、curl ifconfig.me 或访问外网，确认源地址为 182.140.240.121。

3.3 ws6 主机侧配置（割接当晚）

  1. 备份：现网 /etc/sysconfig/network-scripts/ 或 netplan 配置、iptables、业务监听端口清单。
  2. Gb1（原公网口）：删除公网 IP 182.140.240.121，可改为 down 或仅保留无 IP（避免与防火墙 WAN 冲突）。
  3. Gb2（业务口）：IP 10.0.0.16，掩码 255.255.255.0。
  4. 默认网关：10.0.0.11（方案甲）或 10.0.0.254（方案乙）。
  5. DNS：61.139.2.69（与现网一致）。
  6. 验证：内网 ping 网关 → 外网访问 → 外网回连映射端口；确认不再在 ws6 上 ip addr 看到 182.140.240.121。
注意：公网 IP 只能出现在防火墙 XGE0/0/0 一侧；若 ws6 Gb1 仍配置同网段地址会导致 ARP/路由冲突，割接前必须摘掉。

四、B 组端口转发（承接原 ws1 DNAT）

原 ws1（10.0.0.11）上的 DNAT 需在防火墙上逐条迁移后再停用 ws1 NAT 进程。ws1 Gb2 网卡保持在线。

  1. 在 ws1 导出当前 DNAT/iptables：iptables -t nat -L -n -v 或现网文档。
  2. 在 USG 上为每条规则创建 目的 NAT：公网 IP/端口 → 内网 B 组主机 10.0.0.x:端口。
  3. 若公网入口仍在极云线路（182.140.146.x 段），映射配置在 GE0/0/0/1 透传链路边界或上游极云 FW，需与运营商/极云确认入口；若入口在西信线，则绑在 182.140.240.121。
  4. 配置 trust/untrust 安全策略 放行映射会话。
  5. 灰度验证单条端口后，再批量切换；最后停用 ws1 NAT 服务。

五、推荐配置顺序（割接日）

  1. 备份防火墙与 ws1/ws6 网络配置。
  2. 配置 XGE0/0/0（西信 WAN）并打通 182.140.240.1。

对象操作

方案甲（防火墙 10.0.0.11 · 主机不改网关）

  1. 准备：备份 ws1 DNAT 规则；确认西信 GE7 参数
  2. 预配：XGE0/0/0 接西信骨干；GE0/0/7 配置 10.0.0.11/24（方案甲）
  3. 激活：启用接口；B 组 ping 网关 10.0.0.11（与现网一致）；验证 A 组公网
  4. 验证：抽测 ws11/ws18/ws19 出网；确认无需改主机 GATEWAY
  5. 收尾：防火墙策略稳定后，择机停用 ws1 NAT 进程（Gb2 网卡保持在线）

方案乙（防火墙 10.0.0.254 · 分步改主机网关）

  1. 准备：同方案甲
  2. 预配：XGE0/0/0 西信 WAN；GE0/0/7 配置 10.0.0.254/24（方案乙）
  3. 激活：ping 10.0.0.254；验证 A 组
  4. 灰度：1~2 台 B 组（如 ws18/ws19）将 GATEWAY 改为 10.0.0.254
  5. 批量：ws11~ws17 等分 3~4 批切换
  6. 收尾：全部切至 .254 后停用 ws1 NAT（Gb2 仍保持在线）

回滚：方案甲恢复 ws1 NAT；方案乙单台改回网关 10.0.0.11。防火墙与 ws1 可短暂并行，注意避免双 NAT。

⚠ 高危 八、常见故障处理与回退

⚠ 故障时执行的紧急操作。非故障情况严禁执行！操作前先截图当前状态。
# ═══ 故障 1：Trunk 口不通（级联中断）═══
# 现象：跨柜服务器不通，STP 显示端口 DISCARDING
display interface GigabitEthernet1/0/31      # 看物理状态+协商速率
display stp brief | include 1/0/31           # 是否被 STP 阻塞
display port trunk | include 1/0/31          # 允许的 VLAN 是否正确
# 修复：如 VLAN 遗漏 → 补齐 port trunk permit vlan 列表
# 如物理 down → 换光模块/网线

# ═══ 故障 2：广播风暴 ═══
# 现象：全网卡顿，交换机 CPU 100%
display cpu-usage                             # 确认 CPU 100%
display counters rate inbound interface | sort -r | head 5  # 找异常流量口
# 应急：临时 shutdown 异常端口
interface GigabitEthernet1/0/X
shutdown            ### ⚠ 临时关闭异常端口 ###
# 排除风暴源后需要 undo shutdown 恢复

# ═══ 故障 3：MAC 表溢出 ═══
display mac-address count                     # 总 MAC 数 — 超过规格 50% 即异常
display mac-address | count by vlan           # 按 VLAN 统计，定位异常 VLAN

# ═══ 回退：恢复配置到割接前 ═══
### 前提：WinSCP 已上传备份的 startup.cfg ###
configuration replace file flash:/backup-startup.cfg  ### ⚠ 替换运行配置 ###
# 替换后检查关键口状态：
display interface brief | include 1/0/31
display stp brief
display vlan 30
